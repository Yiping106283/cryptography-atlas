Overview

Private information retrieval

Protocols that let a client fetch one entry of a public database held by one or more servers without revealing to the servers which entry it wants.

What it is

A database of N entries sits on one or more servers. A client wants entry i and must not reveal i to any server. Downloading the whole database is always private; private information retrieval (PIR) asks for less communication and, in later work, for less server computation. The problem is due to .

Two independent choices define a setting: how many servers hold copies of the database, and what kind of privacy is required. Information-theoretic privacy means each server's view is independent of i, even for an unbounded server. Computational privacy means no efficient server can tell two indices apart, under a hardness assumption.

Core notions

What is measured

  • Communication: bits exchanged per query; the trivial solution sends N entries.
  • Rate: entry size divided by response size; rate near 1 means the answer is barely longer than the entry.
  • Online server work: computation per query. Without preprocessing it is at least linear in N, because a server that skips an entry learns that it was not requested ().
  • Server storage: what the server keeps besides the database, such as an encoded copy of it.
  • Client state: what a client keeps between queries, such as a hint about the database or a secret key.

Preprocessing, the way around linear work

  • None: the server stores only the database and reads all of it for every query.
  • Client-specific hint: each client fetches a private hint once and then queries in sublinear time (); hints go stale when the database changes.
  • Shared hint: one public hint serves every client and makes the online step fast, though still linear ().
  • Server preprocessing: the server encodes the database once and then answers anyone in sublinear time while clients keep nothing; this is doubly efficient PIR, or DEPIR ().

Main approaches

  • Matching-vector codes: replicated databases queried through matching-vector codes give subpolynomial communication with three or more servers () and with two (), with information-theoretic privacy.
  • Distributed point functions: compact secret shares of a point function give lightweight two-server PIR with computational privacy ().
  • Homomorphic query compression: the client encrypts a selection vector under (Ring-)LWE and one server computes the inner product homomorphically (, ).
  • Matrix–vector protocols with a shared hint: LWE-based schemes whose online step runs at memory speed (), and successors that drop the hint (, , , ).
  • Client preprocessing with sublinear online time: pseudorandom sets give about N​ server time per query, with two servers () or one (, , , ).
  • Server preprocessing (DEPIR): polylogarithmic online time after O(N1+ε) preprocessing under Ring-LWE (), and an information-theoretic multi-server variant ().

This topic covers index PIR for public databases: one server or several non-colluding servers, information-theoretic or computational privacy, and every preprocessing model above. Keyword, symmetric and batch PIR, ORAM, private writes, verifiability, and quantum or coded-storage PIR are outside it unless a covered result depends on them.
